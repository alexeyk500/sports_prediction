# navigation-icon-refactor

## Цель

Отрефакторить иконки нижней навигации приложения так, чтобы визуально они соответствовали приложенному дизайн-референсу и одинаково корректно работали в светлой и тёмной темах.

Источник визуальной правды: `reference-navigation-design.png`.

Новые SVG-референсы иконок:

- `assets/matches.svg`
- `assets/cup.svg`
- `assets/rating.svg`
- `assets/profile.svg`

Эти SVG используют `currentColor`; активное/неактивное состояние должно задаваться цветом контейнера/ссылки, а не отдельными версиями файлов.

## Что нужно сделать

Сначала найди реальный компонент нижней навигации, его стили и текущий способ рендеринга иконок. Не делай слепой global replace и не меняй маршрутизацию/поведение вкладок.

Замени текущие иконки для пунктов:

- Matches
- Cup
- Rating
- Profile

на локальные иконки, воспроизводящие SVG из `assets/`.

Предпочтительная реализация: локальные React-компоненты с inline SVG/path markup, чтобы `currentColor` наследовался напрямую. Не подключай новую библиотеку иконок только ради этой задачи. Если проект уже имеет устойчивый локальный icon abstraction, встрои новые glyphs в него, не нарушая текущую архитектуру.

## Визуальные требования

Иконки должны выглядеть как в `reference-navigation-design.png`:

- Matches: футбольный мяч, outline-style.
- Cup: кубок, outline-style.
- Rating: три вертикальных столбца возрастающей высоты с округлыми концами.
- Profile: заполненный силуэт пользователя.
- Все иконки должны иметь одинаковый визуальный вес и занимать сопоставимую площадь.
- Базовый размер glyph: ориентир 28x28 px. Не увеличивай весь bottom-nav только ради иконок.
- Активная вкладка использует акцентный синий цвет, неактивные — secondary/muted text color темы.
- Цвета должны приходить из существующих theme tokens/CSS variables. Не хардкодь отдельные light/dark hex-значения, если токены уже существуют.
- В светлой теме неактивные иконки должны быть заметно серыми, но не слишком тёмными.
- В тёмной теме неактивные иконки должны иметь достаточный контраст на тёмном фоне, как в референсе.
- Активное состояние иконки и подписи должно использовать один и тот же semantic accent color.
- Не добавляй фон, круг, badge или border вокруг активной иконки, если этого нет в текущем дизайне.

## Поведение и доступность

Сохрани без изменений:

- маршруты вкладок;
- active-state detection;
- кликабельную область;
- порядок вкладок;
- подписи Matches / Cup / Rating / Profile;
- mobile safe-area/padding;
- keyboard navigation и aria-атрибуты, если они уже реализованы.

SVG должны быть декоративными относительно текстовой подписи: не создавай дублирующее озвучивание screen reader'ом. Используй `aria-hidden="true"` / `focusable="false"` там, где это соответствует текущему icon abstraction.

## Архитектурные ограничения

- Не добавлять новую dependency для иконок.
- Не хранить отдельные SVG для active/inactive состояния.
- Не дублировать одинаковую разметку SVG в нескольких местах.
- Не менять backend/API/domain logic.
- Не менять названия разделов и маршруты.
- Не затрагивать иконки вне bottom navigation без явной необходимости.

## Проверка

Проверь минимум:

1. Светлая тема: все четыре вкладки, активное и неактивное состояние.
2. Тёмная тема: все четыре вкладки, активное и неактивное состояние.
3. Каждая вкладка корректно становится активной на своём route.
4. Иконки не прыгают по размеру/вертикали при переключении вкладок.
5. Label baseline и расстояние icon -> label остаются визуально ровными.
6. Нет layout shift после загрузки.
7. TypeScript/lint/tests проекта проходят для затронутой области.

## Критерий приёмки

Bottom navigation визуально соответствует `reference-navigation-design.png`: формы glyphs, относительный размер, stroke/fill характер и active/inactive palette. Иконки являются локальными, theme-aware, не требуют новой библиотеки и не меняют функциональное поведение навигации.
